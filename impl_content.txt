7.1 Chapter Overview  
 
This chapter describes the implementation of the proposed SalesSense forecasting system, 
translating the design and algorithmic structures presented in Chapter 6 into a functional 
prototype. The implementation phase focused on developing modular components  for data 
preprocessing, feature engineering, XGBoost -based revenue forecasting, inventory 
recommendation logic, and SHAP -based explainability. Following the layered architecture 
defined earlier, each module was developed and integrated to ensure accuracy,  
maintainability, and usability. This chapter outlines the technologies used and explains how 
the system design was transformed into a working machine learning application.

7.3 Core Functionalities Implementation

7.3.1 Exploratory Data Analysis (EDA)  
➢ Before training the model, an exploratory analysis was conducted on the dataset 
(generated from files/*.xlsx and april.csv) to understand sales distribution and identify 
data quality issues.  
➢ Dataset Declaration: The system utilizes a proprietary dataset of monthly sales 
records from a retail spices sales shop . 
➢ Dataset Size and Time Range:The dataset consists of 43 usable monthly records 
covering the period from April 2022 to January 2026. The first three months were 
excluded during preprocessing due to insufficient lag values required for feature 
engineering.  
➢ Data Split:Training Data ( 40 Months ): Used to teach the XGBoost model the 
relationship between time (Month) and Revenue.  
➢ Testing Data ( 3 Months ): Used to validate the model's accuracy on unseen future 
months.  
➢ Features Used:The final model was trained using the following features: MonthNum, 
MonthOfYear, Lag1, Lag2, Lag3, RollingMean3, and RollingStd3. These features 
were specifically engineered to capture temporal dependencies and seasonal patterns 
in sales data .

7.3.3 Code Structure & Organization  
The codebase follows a clear separation of concerns pattern:  
1.backend/: Contains all business logic and ML algorithms.  
2.main.py: The Controller, handling API requests.  
3.data_processor.py: The Service, handling data logic.  
4.frontend/: Contains the presentation layer.  
5.src/App.jsx: The View, responsible for rendering charts and managing state.  
6.Design Pattern: The backend implements a Service -Controller pattern (implicitly), where  
7.Data_processor.py acts as the service layer providing clean data to the main.py  controller. 
The frontend uses the Component -Based pattern inherent to React.  
 
 
7.3.4 Integration  
Integration between the Frontend and Backend is achieved via RESTful APIs.  
1.Request: The React frontend uses axios to send an HTTP GET request to 
http://localhost:8000/api/forecast.  
2.Processing: FastAPI receives the request, triggers the training pipeline in  
main.py, and generates the JSON response.  
3.Response: The JSON data (containing predictions and SHAP values) is sent back to the 
frontend.  
4.Rendering: React updates the state (setForecast), causing the react -chartjs -2 components to 
re-render with the new data.  
This seamless integration allows the complex ML operations to occur invisibly to the user, 
who simply sees the dashboard update in real -time.

This section is emphasized to show the technical challenges experienced in the process of 
creating SalesSense and the engineering solutions that were adopted to address them.  
 
7.5.1 Quality of Data and Inconsistency.  
Challenge: Unstructured nature of the legacy data was the major challenge. All the source 
files were the manually created Excel books of books (files/*/.xlsx) that were not made by 
machines.  
Problems: Combined rows, disparate date headers (e.g. one row says For April 2024 and 
another April -24), and the rows with Particulars showing up with varying indices.  
Impact: Standard library functions (such as pd.read_excel) were not able to read the tables, 
and empty or misaligned datasets were obtained.  
Solution: We adopted a home made Robust ETL Parser in data_processor.py  
Dynamic Header Detection: The script does not predetermine the row number on which it 
will look at the headers but scans the first 50 rows to find the keyword Particulars.  
Regex Cleaning: A clean_value Regular Expression (re.search(r"([ \d.]+), s)) is a function 
created to take a numerical value of a string such as 10 kgs or 1,200.00 and is capable of 
overcoming the error of human formatting.  
 
7.5.2 Overfitting of Model to Small Dataset.  
Difficulty: The dataset used was monthly data in a limited number of years. Deep Learning 
models (such as LSTMs) generally need thousands of observations to be generalized.  
Impact: Early work with complex neural networks achieved poor performance as the model 
overfitted, that is, it remembered the training data but could not make accurate predictions of 
future trends.  
Rationale: XGBoost (Extreme Gradient Boosting) was chosen over Deep Neural Network.  
Why: XGBoost is an ensemble algorithm (a decision -tree) which works remarkably well with 
a small, structured tabular data.  
Regularization: To ensure that the model does not get too complicated, tuned 
hyperparameters (learning rate 0.05, max depth=3) so that the model only learns the overall 
trend and not noise.
